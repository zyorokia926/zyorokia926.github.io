Shulker AutoFetch 機能書 (v1.0.0 / プロトコル版数 2)
================================================================

1. 概要
-------
Minecraft Java 1.19.4 / Fabric 用の Litematica アドオンです。
Litematica で設計図を使って建築するとき、必要なアイテムがインベントリに無ければ、インベントリ内のシュルカーボックスの中身から
自動で取り出し、「今手に持っているホットバーの枠」へ入れます。取り出しはサーバーが検証して確定します。

対象とする Litematica の操作(3つ)
  (1) 設計図ブロックへのホイールクリック(Pick Block。既定は中ボタン)
  (2) Easy Place(使用キー押下 / 押しっぱなし)
  (3) Easy Place の精密設置プロトコル(Easy Place Protocol: V3 / V2 / Slabs only)= 「ProPlace」

2. 動作環境
-----------
  Minecraft 1.19.4 / Fabric Loader 0.15.11 以上 / Java 17 以上
  Fabric API 0.87.2+1.19.4 以上(クライアント・サーバー両方)
  Litematica 0.14.x(確認 0.14.7)・MaLiLib 0.15.x(確認 0.15.4)  ※クライアントのみ
  導入先: クライアントとサーバーの両方(シングルプレイはクライアントのみで動作)

3. 機能一覧
-----------
F1. インベントリ優先
  目的   : 既に持っているアイテムを無駄に箱から出さない。
  条件   : 必要なアイテムが、メインインベントリ36枠(ホットバー9 + 通常27)のどこかにある。
           (アイテムとNBTが一致するもの。オフハンドは含まない)
  動作   : シュルカーボックスは一切検索・操作しない。Litematica 標準の動作がそのまま行われる
           (インベントリ内のアイテムを手に持つ処理は Litematica 本来のもの)。

F2. シュルカーボックス内の検索
  条件   : F1 に当てはまらない(インベントリに無い)。
  対象   : メインインベントリ36枠の中の、すべての色のシュルカーボックス。箱を手に持ったり開いたりする必要はない。
  一致   : アイテムとNBTが一致するエントリ(名前付きなど、NBTが違うものは別物)。
  読み取り: 箱のアイテムデータ(BlockEntityTag.Items)を直接読む。データが無い箱、LootTable が未展開の箱、
           Items が不正な箱は「該当なし」とし、存在を推測しない。

F3. 最大数のスタックから取り出す
  選択   : 複数の箱・複数のエントリに該当があるときは、数量が最大のエントリを選ぶ。同数なら若い(インベントリ番号の小さい)スロットの箱。
  取り出し量: そのエントリの全量。ただしアイテムの最大スタック数まで。(例: 石 64 と 30 があれば 64 を取り出す)
  残り   : 余りはエントリに残る。エントリが空になれば削除し、箱の中身が全て空なら箱のタグごと除去(普通の空の箱に戻る)。
  保護   : 解釈できないエントリ(削除された Mod のアイテム等)は書き換えずに保持する。

F4. 手持ちの枠へ配置・入れ替え
  配置先  : 今手に持っているホットバー枠(選択中の枠)。必ずその枠に入る。
  入れ替え: その枠に元からあるアイテムは、空いているスロットへ退避する(通常27枠を優先、なければホットバー)。破棄・上書きはしない。
  満杯   : 退避先が1つも無い場合は、何も変更せず終了する(アイテムは失われない)。
  特例   : 取り出し元の箱自身を手に持っているときは、中身を減らした箱のほうを退避する。

F5. 即時反映
  動作   : 取り出しが必要なとき、サーバーと全く同じ処理をクライアントのインベントリへ先に適用する。
           その後で Litematica の元の処理を続けるので、ホイールクリックと同じtickで選択中の枠にアイテムが入る。
           Easy Place では同じ押下のまま設置まで進む(サーバーへの要求パケットは設置パケットより先に送られ、順序が保たれる)。
  根拠   : クライアントの反映は「予測」であり、確定はサーバーが行う(F9)。

F6. ホイールクリック対応
  経路   : WorldUtils.doSchematicWorldPickBlock → InventoryUtils.schematicWorldPickBlock
  設定   : shulkerFetchWheelClick で有効/無効。

F7. Easy Place 対応
  経路   : WorldUtils.doEasyPlaceAction → InventoryUtils.schematicWorldPickBlock
  動作   : 使用キーを押し続けると、足りないブロックがその都度箱から補充され、そのまま設置される。
  設定   : shulkerFetchEasyPlace で有効/無効。

F8. ProPlace(精密設置プロトコル)対応
  動作   : Easy Place が精密設置プロトコル(V3 / V2 / Slabs only)で動作しているときも、F7 と同様に取得する。
  設定   : shulkerFetchProPlace で有効/無効。精密設置プロトコル使用中は shulkerFetchEasyPlace と shulkerFetchProPlace の両方が必要。
           プロトコルが None のときは shulkerFetchEasyPlace のみで判定。

F9. サーバーによる検証と同期
  サーバーは要求を受けるたびに次を確認し、すべて満たしたときだけ実行する。
    - プロトコル版数が一致、プレイヤーが生存・非観戦
    - 別の画面(コンテナ・カーソル操作)を開いていない
    - 要求の選択枠番号が、サーバー側の選択枠と一致
    - クールダウン(既定2tick)内の連続要求でない
    - 実インベントリを再検索し、まだインベントリに無く、箱に該当アイテムがあり、退避先がある
  実行   : 箱のコピーを編集し、箱・退避アイテム・配置アイテムの変更を同時に確定(失敗途中の状態を作らない)。
  同期   : 変更後に全クライアントへインベントリを同期してから応答する。
  拒否   : OK 以外の結果のときは、全スロットを送り直し、クライアントの先行適用を権威状態で上書きする(巻き戻し)。
  結果   : アイテムの複製・消失は起きない。

F10. 処理負荷への配慮
  - インベントリに既にあるときは、箱の検索自体を行わない(F1)。
  - 箱の検索は1回だけ。箱内エントリは先に生のアイテムIDで絞り込み、候補だけを解析する。
  - 検索・取り出しに失敗した同じアイテムは、40tick の間、再検索・再要求しない(押しっぱなしでも毎tick走査しない)。
  - 未応答の要求は最大4件、100tick で打ち切り。
  - サーバー側は1要求につき1回の取り出しのみ。

F11. 失敗時の挙動(失敗の画面通知なし。ホットキー実行時の通知は F12)
  対象のアイテムがどこにも無い / 満杯 / サーバーが拒否 / 応答なし / サーバー未導入・版数不一致 のときは、
  何も起こさず Litematica の標準動作に任せる。画面への通知表示はしない(デバッグログのみ)。

F12. 設定・言語・ホットキー
  表示言語   : 日本語・英語(ゲームの言語設定に従う)。設定名・説明・通知はすべて両言語に対応。
  クライアント(MaLiLib 画面。ホットキー M + F で開く。ファイル config/shulkerfetch.json)
    shulkerFetchEnabled     Mod 全体の有効/無効                (既定 true , トグル M + T)
    shulkerFetchProPlace    精密設置プロトコル使用時の取得     (既定 true , トグル なし)
    shulkerFetchEasyPlace   Easy Place 時の取得                (既定 true , トグル なし)
    shulkerFetchWheelClick  ホイールクリック時の取得           (既定 true , トグル なし)
    shulkerFetchDebugLog    デバッグログ                       (既定 false, トグル なし)
    shulkerFetchOpenGui     設定画面を開く                     (ホットキー M + F)
  トグルホットキー: 各ON/OFF設定に割り当て可能。実行すると、Litematica 等の masa 系 Mod と同じように
                    ホットバーの上に「Shulker AutoFetch: 〇〇 を ON/OFF にしました」と通知が出る(ON=緑、OFF=赤)。
  サーバー(config/shulkerfetch-server.json)
    enabled               サーバーでの有効/無効           (既定 true)
    cooldownTicks         同一プレイヤーの最小要求間隔    (既定 2、範囲 1〜200)

F13. 通信仕様(Fabric API Networking、プロトコル版数 2)
    shulkerfetch:hello     S→C  参加時: 版数、Mod版数
    shulkerfetch:request   C→S  版数、要求ID、選択中の枠番号、要求アイテム(個数1)
    shulkerfetch:response  S→C  要求ID、状態、取り出し数、配置スロット
  状態: OK / NOT_FOUND / INVENTORY_FULL / ALREADY_AVAILABLE / BUSY / DISABLED / BAD_REQUEST / PROTOCOL_MISMATCH

F14. 未導入・版数不一致
  サーバーに Mod が無い、または版数が違うときは、クライアントは要求を送らず(ログに警告のみ)、Litematica 標準動作のままになる。
  サーバー側 Mod が必要な機能であり、サーバーにも導入が必要。

4. 動作シナリオ例
-----------------
  A. インベントリ優先: ガラスが箱の外にある → ホイールクリック → 箱の外のガラスが使われ、箱のガラス(16)は減らない。
  B. 最大数優先: 青い箱に石 64 と 30、石はインベントリに無い → ホイールクリック → 石 64 が選択中の枠に入る。箱には 30 が残る。元の枠のスティックは空きスロットへ退避。
  C. Easy Place: 石 → ガラス → 木材と続けて設置。足りなくなるたびに箱から補充され、同じ押下で設置される。
  D. ProPlace: プロトコルを Slabs only にして、上半分のハーフブロックも同様に取得・設置。
  E. 見つからない: ダイヤブロックなど、インベントリにも箱にも無い → 何も起きない。
  F. 満杯: 36枠すべて埋まり退避できない → 何も起きない(失われない)。空きを作って再度クリックすると取得される。
  G. 設定オフ: shulkerFetchWheelClick をオフ → 箱から取得されない。オンに戻すと取得される。

5. 内部構成
-----------
  common : Protocol / ShulkerInventory(検索・取り出し) / FetchTransaction(取り出しの1トランザクション)
  server : ServerFetchHandler(検証・実行・同期・巻き戻し) / ServerConfig
  client : FetchController(先行適用と要求) / mixin(MixinInventoryUtils・MixinWorldUtils) / config
  Mixin  : InventoryUtils.schematicWorldPickBlock の HEAD(取得処理)、
           WorldUtils.doEasyPlaceAction / doSchematicWorldPickBlock(呼び出し元の記録のみ)。 defaultRequire=1 で、適用失敗は起動時に判明する。

6. 検証状況
-----------
  実施済み: クリーンビルド、ユニットテスト17件、専用サーバー起動、実クライアント(Litematica / MaLiLib 実物)+専用サーバーでの
            Mixin 適用(エラー0)、同tickでの手持ち枠配置、最大スタック優先、インベントリ優先、Easy Place での取得と実設置、
            Slabs only、見つからない / 満杯 / 設定オフの無動作、同一tickの2要求でのサーバー拒否と巻き戻し(最終状態の一致)。
  追加実施: X11 の実イベント(xdotool)による入力で、中ボタンクリック(手持ちが石64に変わる)、右クリック長押しの Easy Place(ガラスを取得して実設置)、
            M + T の通知(日本語・英語)、M + F の設定画面(日本語・英語)を確認。
  未検証  : 物理ハードウェアの入力そのもの、Mod未導入サーバー・版数不一致の実機確認、複数人同時接続、
            他 Mod との併用、通常の Fabric ランチャー(intermediary)での起動。

7. 既知の制限
-------------
  - 探索対象はメインインベントリ36枠のシュルカーボックスのみ(オフハンド・エンダーチェスト・設置済みの箱は対象外)。
  - 取り出しは1要求につき1スタック。
  - 手持ちの枠にアイテムがあり、退避先の空きスロットも無いときは動作しない。
  - クリエイティブ・観戦モードでは何もしない。
  - サーバー側にも導入が必要(未導入ならクライアントだけでは取得できない)。
  - 対応は Litematica 0.14.x / MaLiLib 0.15.x。内部メソッドが変わると起動時に Mixin エラーで判明する。
